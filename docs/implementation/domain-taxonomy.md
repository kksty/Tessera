# 测试域分类与项目类型边界

> 状态：协议字段、Decide 写入与前端「按测试域汇总」已实现；项目类型（`project.track`）仍是设计稿。前端默认按测试域汇总，并保留按节点类型的临时视图。`client` / `forensic` 保留域仍未进入枚举。
>
> 适用范围：黑板汇总、Step 分类、后续移动端 / 桌面 / IR 评估的边界判断。

## 背景与取舍

黑板目前按节点展开，大项目会变成一张很大的图。已经试过两种降维方式：

- **按节点类型汇总**：当前前端已有临时视图（`apps/web/src/graph-summary.ts`、`Blackboard.tsx`），把起点、目标、事实、任务、发现各收成一个框。视觉上干净，但在 95 条事实的样本上，事实框内部仍有 92 条事实→事实的因果边，只能计数、不能展开；总览能看出构成，看不出因果。
- **按入口 surface 汇总**：在同一个样本上测到 199 个不同的 host+path、1043 对跨 surface 的 Step 关系，94 条非 origin 事实里只有 84 条能归到主 surface，60 条同时涉及多个 surface。粒度太细、噪音太大，作为分组键会比原图更大，放弃。

因此需要一个**语义稳定、数量有界、每个 Step 能选一个**的分类：测试域。

## 1. 结论

1. **按“测试域”汇总，不按阶段汇总。** 域回答“这是哪类问题”，时序交给图里已有的边；阶段分组会让节点和边重复表达先后，而且测试会来回跳。
2. **分类单位是 Step，不是项目。** `Step.test_domain` 是可选枚举；Fact 从生产 Step 继承，Finding 从来源 Step 继承，不单独打标。
3. **现在不引入项目类型。** 域表做成超集，未使用的域不显示；新增域是增量改动，不需要迁移。一个项目可以同时包含 Web 和客户端 Step。
4. **只有工作流整体不同才需要项目类型。** 工具链、任务契约、报告模板、数据源、授权或调度至少有一项整体分叉，且无法用节点字段表达时，才考虑项目类型；IR / 取证是目前唯一候选。
5. **逆向是手法，不是域。** Web 的 JS 审计归“入口与前端”；只有目标本身是 APK / 二进制 / 桌面程序、且 Worker 具备逆向工具链时，才增加“客户端与逆向”域。
6. **溯源要分三种。** 证据溯源是图本身的能力；攻击归因是 IR 生命周期，不是渗透域；反溯源 / 痕迹清理是后渗透的高风险子项，默认不做。

## 2. 三个轴

| 轴 | 回答 | 存放 | 是否参与分组 |
| --- | --- | --- | --- |
| 测试域 | 测什么 | `Step.test_domain` | 是，黑板的汇总键 |
| 手法 | 怎么做 | 暂不落库；需要时加 `Step.method` 标签 | 否，只做徽章 / 筛选 |
| 对象 | 对什么 | `asset_id`、`objects`、`request.url`、`surface` | 否，二级标签 |
| focus | 域内细节 | `Step.focus` | 否，展开域后显示 |

手法是横跨域的多选标签（主动扫描、手工验证、静态逆向、动态调试、流量分析、代码审计、爆破），不改变黑板结构，因此不放进第一版。第一版只落 `test_domain` 和可选的 `focus`。

## 3. 九个测试域（+ other）

| 代码 | 名称 | 收什么 | 不收什么 |
| --- | --- | --- | --- |
| `recon` | 资产与暴露面 | 子域、端口、服务、指纹、目录、敏感文件、TLS、响应头 | 从已控主机发起的横向；登录测试 |
| `entry` | 入口与前端 | 页面、JS、API 清单、参数、客户端存储 | 二进制 / APK 逆向（未来 `client` 域）；认证逻辑验证 |
| `auth` | 认证与会话 | 登录、验证码、令牌、Cookie、会话固定 | 取得会话后的凭据获取 |
| `access` | 授权与访问控制 | 越权、IDOR、功能级鉴权 | 认证绕过（归 `auth`） |
| `inject` | 输入与注入 | SQLi、XSS、命令、SSRF、模板注入 | 文件上传 / 路径遍历（归 `file`） |
| `file` | 文件与上传 | 上传、下载、路径遍历、解析 | 命令注入（归 `inject`） |
| `config` | 配置与传输 | CORS、错误泄露、请求走私、方法覆盖、TLS 策略 | 端口 / 服务发现（归 `recon`） |
| `logic` | 业务逻辑 | 流程绕过、竞态、支付 / 积分 | 通用越权（归 `access`） |
| `post` | 后渗透与影响 | 提权、凭据获取、横向可达、持久化、影响证明 | 外部扫描；登录处认证测试 |
| `other` | 其他 / 未分类 | 旧项目、人工临时 Step、确实装不下的 | — |

`client`（客户端与逆向）和 `forensic`（取证与溯源）是**保留域**，不进第一版枚举；出现真实项目和工具链后再加。九个核心域加 `other`，共十个可选值。

## 4. 判定边界

四条规则，按顺序判断：

1. **有没有立足点**：从外部直接观测归 `recon`；从已控主机 / 会话发起归 `post`。
2. **是否尝试跨权限边界**：只记录版本 / 配置归 `recon` 或 `config`；实际尝试提权、横向、取凭据归 `post`。
3. **是观测还是测控制**：看端口、指纹、TLS 支持归 `recon`；验证 CORS 策略、错误泄露、走私、方法覆盖归 `config`。
4. **是测认证还是取凭据**：在登录入口试口令 / 验证码归 `auth`；取得会话后从浏览器、文件、内存里取凭据归 `post`。

### 4.1 后渗透

`post` 内部用 `focus` 的固定前缀区分，不再拆顶层域：

| focus | 含义 |
| --- | --- |
| `提权：SUID` | 本地权限提升 |
| `凭据：浏览器存储` | 从已控会话获取凭据 |
| `横向：SMB 可达` | 从已控主机访问其他主机 / 服务 |
| `持久化：计划任务` | 持久化（默认不做） |
| `影响：读取配置` | 只读证明实际影响 |
| `反溯源：清理日志` | 痕迹清理（默认不做，高风险） |

前缀固定、细节自由；冒号后写这个站的具体对象或技术。UI 在 `post` 框的第二行显示前缀分布，例如“提权 5 · 凭据 4 · 横向 3”。

### 4.2 逆向

- **Web 项目**：逆向是手法，不是域。JS 静态审计、提取 API、找硬编码密钥，归 `entry`，`focus` 写“前端：app.js 静态审计”。
- **移动 / 桌面项目**：目标本身是 APK / 二进制 / 桌面程序时，才增加 `client` 域；它需要 jadx / Ghidra / apktool 等工具链，当前 Worker 工具参考里没有这些工具，先不加空域。
- 同一个 Step 既做逆向又做认证时，按“回答的主要问题”选一个主域，细节写 `focus`；不支持多主域，避免同一节点出现在两个组里。

### 4.3 溯源

| 说法 | 归属 | 处理 |
| --- | --- | --- |
| 证据溯源（这条发现由哪些 Fact / Step / Evidence 支撑） | 图本身 | 已有来源链 / 证据链，不需要分类 |
| 攻击归因 / 蓝队溯源 | IR 项目模式 | 生命周期是接报 → 取证 → 时间线 → 归因 → 处置，不能混进渗透域表 |
| 反溯源 / 痕迹清理 | `post` 的 `focus` | 高风险，默认不做；需要时单独标记 |
| 资产溯源（这个资产从哪来） | 资产发现边 | 已由资产星图 / 发现边表达，不是测试域 |

## 5. 数据模型与继承

```ts
// packages/protocol/src/schemas.ts
export const TEST_DOMAINS = [
  "recon", "entry", "auth", "access", "inject",
  "file", "config", "logic", "post", "other",
] as const;
export const testDomainSchema = z.enum(TEST_DOMAINS);

// packages/protocol/src/models.ts
export type TestDomain = (typeof TEST_DOMAINS)[number];

interface Step {
  /** 测试域；旧数据缺失时显示「未分类」。字段名不用 domain，避免和 DNS 域名混淆。 */
  test_domain?: TestDomain;
  /** 域内细节，≤20 字；后渗透使用「子类：细节」。 */
  focus?: string;
}
```

- 字段可选，不设默认值；缺失即「未分类」，不启动迁移、不自动回填。存储按记录 JSON 落库，新增字段不需要数据库迁移。
- 新 Step 由 Decide 在 `submit_decisions.steps[]` 填写；人工建单（`manualStep`）可直接带入；旧 Step 可用 `submit_decisions.updates[]` 补分类，不强制。
- 补分类不改 Step 版本，也不计入 `planning-changes.ts` 的业务比较：它是分组标签，不是新的规划输入。
- Fact 不落字段：通过 `step_id` / 生产关系继承生产 Step 的 `test_domain` 与 `focus`；没有生产者的孤立事实归 `other`。
- Finding 不落字段：按 `step_id`、修订 Step、生产边、来源 Fact 的顺序继承；继续保留现有的 `kind` 和 `identity.category`，不把两者合并。
- `test_domain` 不参与完成校验、Review 结论、授权或报告入库判定，只用于分组、筛选和统计。
- Decide 的 Step 索引行带一个短码 ` [recon]`（已分类才带），让决策者看到哪些旧任务还没分类；Execute / Review 的投影仍不加，避免每个 Step 多几个字符。
- 人工可以在黑板节点详情里直接改测试域与 focus（`PUT /api/projects/:id/fgs/steps/:step/classification`，事件 `step.classified`）：同样不改版本、不推进规划，已完成项目也能整理分类。

## 6. 项目类型：现在不要，什么时候才真的需要

本文的“项目类型”和“模式”指同一个项目级 `track`；在真正实现前不落字段。

### 6.1 现在不加

- 分类单位是 Step，不是项目；一个项目完全可以同时有 Web 和 App 的 Step，项目类型会强迫二选一。
- 创建项目的 Schema 目前只有 `title` / `origin` / `goal` / `hints`（`packages/protocol/src/schemas.ts`）；[项目说明](../project.md)明确写“创建项目不再接受 objective / assessment 类型参数”。为了 UI 分组把类型请回来，会重新引入创建、提示词、报告、筛选和迁移的分叉。
- 域表是超集：没用的域不渲染；以后加“客户端与逆向”只是加一个枚举值、一条提示词和一处 UI 文案，旧数据不受影响。

### 6.2 三个条件

只有**同时满足**以下三条，才引入项目类型：

1. **不能表达为节点字段**：差异无法用 `test_domain`、`focus`、`method`、`asset`、`scope` 这些数据表达。
2. **任务契约或交付物整体变化**：三类角色的提示词、工具权限、授权语义，或报告章节、评分、证据类型，至少有一项整体不同，而不是多一个标签。
3. **混在一起会产生实际歧义或风险**：例如 IR 的只读取证授权与渗透的主动测试授权混在同一项目里；或数据源完全不同，无法共用同一套 Run / 证据契约。

只满足“换一套词表”的，不加类型，加域。

### 6.3 决策表

| 变化 | 动作 |
| --- | --- |
| 只多一个测试域 / 词 | 加枚举值，不加项目类型 |
| 只多一种工具（jadx、Ghidra） | 先做 Worker 能力；需要时加手法标签，不加项目类型 |
| 只是报告章节或评分不同 | 优先做报告配置（report profile），不加项目类型 |
| 目标类型不同（Web + 移动端混合） | 加资产类型和 `client` 域，混合项目自然支持 |
| 数据源不是目标请求（日志、PCAP、镜像、EDR） | IR 类型候选 |
| 授权 / 调度 / Run 生命周期整体不同 | 项目类型候选 |
| 只是 UI 想换个分组 | 不加，改汇总键 |

### 6.4 IR / 取证

IR = Incident Response（事件响应 / 应急响应）：处理已经发生的事件，而不是主动去测试目标。它的生命周期与渗透不同，大致是：

准备 → 接报 / 发现 → 检测与确认 → 遏制 → 根除 → 恢复 → 复盘。

取证、时间线和归因通常与这些阶段并行；归因不是每个 IR 的必经步骤，很多事件只做到遏制、根除和恢复。

与渗透的差别：

- 起点是告警、事件线索或外部通报，不是 `origin`；
- 数据源是日志、流量、磁盘 / 内存镜像、EDR 记录，不是对目标发请求；
- 授权是只读取证与保全，不是主动测试；
- 完成标准是时间线、证据完整性、遏制 / 恢复确认，不是漏洞清单；
- 报告是事件时间线、根因、影响和处置建议，不是漏洞列表。

这是目前唯一可能真正需要项目类型的场景。

如果真要做，两种选择，二选一，不要混合：

1. **加一个可选 `project.track`**（默认 `general`），只选择域词表、提示词和报告模板；旧项目读作 `general`，不回填、不自动从 goal 推断、不允许在有 Step 后随意切换。
2. **单独的产品面 / 应用**，不复用渗透项目的 Run 和完成契约。

现在不预建，等有真实 IR 项目再决定。

### 6.5 移动 / 桌面

- 先加工具链，再加 `client` 域；没有工具链时加域只会得到空框。
- 混合项目（API + 客户端）用同一个项目、不同 Step 的域表达，不需要项目类型。
- 只有当移动端的任务契约整体不同（APK 证据类型、不同的报告模板、不同的工具权限）时，才升级成模式；不是“有移动端目标”就加类型。

### 6.6 红队 / 后渗透

- 仍是主动测试工作流，差异主要在授权范围、目标和停止条件；优先用范围字段、Hint 或授权记录表达，不加项目类型。
- 如果后渗透成为项目主体，可以把 `post` 的子前缀提升为报告 / 汇总层的顶层域，但这是**报告配置**，不一定要落成项目类型。

### 6.7 如果以后确实要加

- 用可选字段，默认 `general`；旧项目读作 `general`，不迁移、不回填、不自动推断。
- 创建时可以选，也可以留空；有 Step 后限制切换，避免同一项目两套契约。
- API / 数据库做增量字段，旧客户端忽略；不新增必填参数。
- 只影响提示词、工具授权和报告模板，不改变图的事务、租约、完成校验和证据契约。
- 不为它写自动迁移，也不把 `objective` / `assessment` 旧类型请回来。

## 7. 提示词预算

只加在 Decide 的 `submit_decisions` Schema 和一句正文里：

```ts
test_domain: z.enum([
  "recon", "entry", "auth", "access", "inject",
  "file", "config", "logic", "post", "other",
]).optional()
  .describe("测试域：recon 资产/信息搜集，entry 入口/前端，auth 认证/会话，access 授权，inject 注入，file 文件，config 配置/传输，logic 业务逻辑，post 后渗透，other 其他"),
focus: z.string().max(20).optional()
  .describe("可选，域内细节，如 提权：SUID"),
```

`updates[]` 也接受这两个字段（不重复长描述），用于补齐旧 Step。正文只写判定边界，不列全表、不举例（`packages/runner/src/prompts.ts` 的 `testDomainGuidance`）：

> 每个新 Step 填 test_domain（固定枚举见 Schema，不确定选 other，不要自造），域内细节写 focus（≤20 字）；无立足点的扫描算 recon，从已控主机/会话发起算 post，登录处测口令算 auth，取得会话后取凭据算 post；旧 Step 可用 updates 补分类，不强制。

实测预算（2026-10，当前源码）：

| 位置 | 增量 |
| --- | --- |
| Decide 工具 JSON Schema | 8,023 → 8,536 字符（+513，约 +6%） |
| 其中 `steps.test_domain` / `steps.focus` | 233 / 80 字符 |
| 其中 `updates.test_domain` / `updates.focus` | 106 / 46 字符 |
| Decide 正文 `testDomainGuidance` | 178 字，相对 3,836 字符的静态 Decide 提示词约 +5% |
| 每行 Step 的 ` [域]` 短码 | 约 7–10 字符/已分类 Step；未分类不加 |
| 合计模型可见增量 | 约 +690 字符 + 每 Step 短码 |

真实 Run 的动态投影通常几千到几万字符，实际占比更小。

- 只有新 Step 多一个短码（2–5 tokens）；更新旧 Step 可以不带。
- Execute / Review / Fact / Finding 都不加字段、不加提示词；`test_domain` 不放进它们的投影。
- 不要把域定义表、每个域的例子、判定表贴进提示词；这些放代码和文档，Schema 里只留一行短描述。
- 静态前缀保持稳定，便于供应商缓存；不要把动态投影混进静态段。

验证方式：

- `pnpm export:work-prompts` 对比加字段前后的真实系统提示词字符数；
- `capacity_plan` 查看真实 Run 的 `task_prompt_chars` / `projection_chars`；
- `tests/runner/decide-schema-budget.test.ts` 断言：四个分类字段合计 ≤500 字符、正文说明 ≤200 字，且 Execute / Review 提示词不包含这段说明。加字段或改描述时先跑这条测试，防止以后往提示词里贴长表。

## 8. 黑板汇总

已实现于 `apps/web/src/graph-summary.ts`（`domainSummaryElements`）与 `Blackboard.tsx`：

- 默认仍是完整图；工具栏「按测试域汇总」开关在链路视图下禁用。汇总开启后，左上角布局选择旁多一个「汇总方式」选择：按测试域（默认）/ 按节点类型（临时视图，保留用于对照）。
- 分组键是 `Step.test_domain`；Step 按自己的域归组，Fact 按生产 Step、Finding 按生产/来源 Step 继承域与 focus。`origin`、范围节点、Goal / 子目标、Hint 是锚点，保持独立节点，不塞进测试域。
- 汇总节点第一行写「域名 × 数量」，第二行写构成（`任务 12 · 事实 30 · 发现 2`，为 0 的项省略）；收起的 `post` 框第三行写 focus 前缀分布（`提权 5 · 凭据 4`）。
- 点框展开该域的真实节点，点空白收起；展开 `post` 先显示 focus 前缀二级框（`提权 ×7`），再展开到 Step / Fact。`post` 只有一个「其他」前缀时不套空框，直接展开到节点。
- 空域不渲染；没有 `test_domain` 的旧节点落在「其他 / 未分类」，不会消失。
- 边按 `source + target + status` 合并并标 `×N`；同域内部边只计数（标签写「含 N 条组内连线」不画自环）；两端都已展开的边保留原 `id` / `step_id`，仍可选中定位。
- 展开/收起与切换汇总方式都会换视角键并重新 `fit`，导出文件名带 `-domain` / `-type` 后缀。
- 展开 `post` 时图例额外提示「后渗透已按 focus 前缀展开」，避免二级框看起来像新的顶层域。
- 汇总视图沿用黑板的可读缩放（`MIN_READABLE_ZOOM`）：域框很多时会略超出画布，可缩小或拖动画布查看；这是与完整图一致的取舍。
- 时间线（项目日志）顶部显示同一口径的统计：各域任务数（空域保留 0 条）、已分类 / 未分类比例、核心域覆盖率，以及输入事实来自其他域的「跨域任务」数；只计未删除、未丢弃的任务，事实与发现按生产任务继承域。
- 运行日志导出（`GET /api/projects/:id/diagnostics`，gzip NDJSON）在 manifest 之后带一条 `domain_coverage`（`schema: tessera.domain-coverage.v1`）：`tasks`、`other_ratio`、`core_domains`、`cross_domain_tasks`、逐域 `domains[]` 与口径说明；导出文件自身就能回答覆盖情况，不需要另开网页。
- 节点颜色、图例仍由 `type` 决定，汇总框用虚线区分。

测试：`tests/web/graph-summary.test.ts` 覆盖分组、继承、`other`、空域隐藏、`×N`、组内边计数、`post` 二级展开与单前缀回退、`focusPrefix` 归一。

## 10. 验收

已通过：

- Schema 接受九个域 + `other`，拒绝未知值；`focus` ≤20 字；旧 Step 缺字段可正常读取，旧客户端提交不需要新字段。
- Decide 规划的新 Step 持久化 `test_domain` / `focus`；`updates` 可补分类且不改版本、不推进 `planning_revision`。
- Fact / Finding 按生产关系继承域（前端汇总测试覆盖）。
- 汇总视图的域计数、内部边计数、跨域边 `×N` 与数据一致；空域不出现；点域展开 / 点空白收起可用；`post` 二级 focus 展开可用。
- Decide 提示词与工具 Schema 增量在预算内；Execute / Review 提示词不包含分类说明（`tests/runner/decide-schema-budget.test.ts`）。
- 创建项目 API 不接受类型参数；数据库没有项目类型字段。
- 旧项目在汇总里显示「其他 / 未分类」，没有自动迁移或回填。

仍需真实样本确认：

- 真实项目的域覆盖与 `other` 比例是否说明域表需要调整（时间线页已能看到数值，但还没有真实样本基线）。
- `test_domain` 是否要出现在 Decide 的 Step 索引投影里（便于补分类，但每个 Step 多几个字符）。

## 11. 非目标

- 不按阶段分组，不为阶段落库。
- 不做按站点自由创造的顶层分类。
- 不做“决策者扫描时顺手打标”的副作用分类。
- 现在不加项目类型、不加移动端 / IR 工具链。
- `test_domain` 不作为完成门槛、Review 结论、授权依据或漏洞入库条件。
- 第一版不支持一个 Step 多个主域；跨域细节写 `focus`。
- 不自动回填旧项目，不从 goal 推断类型。

## 12. 待定

- `focus` 是否只在 `post` 强制使用固定前缀；其他域是否也要求「子类：细节」。
- `client` 域是现在预留枚举值，还是等第一个客户端项目再加。
- IR 最终是「项目类型 + 同一产品面」，还是独立产品面；等真实需求再定。

已定：

- `post` 前缀是软约束——Schema 只校验 ≤20 字，前端把不认识的写法归入「其他」，不因拼写差异拒绝提交或重试。
- `test_domain` 进 Decide 的 Step 索引（每行一个短码），不进 Execute / Review 的投影。
- 人工补分类走节点详情里的下拉 + 细节输入，不改版本、不推进规划。
- 汇总视图沿用黑板的可读缩放：域框很多时会略超出画布，用「适应黑板」或滚轮缩小看全；不改成默认 fit，否则 13px 标签会缩到 6px 以下、整块文字消失。
