# M6 固定小集

原两轮已于 2026-10-20 收尾，结果按结论不足归档。当前暂缓扩大和重复 M6，不作为现有功能完善的前置条件；M6 是模型效果对照，与最终报告交付分别验收。以下命令保留供复核及将来另行安排使用，不代表当前待执行任务。针对具体缺陷使用已配置模型做有预算的隔离验证，应单独保存记录，不改写或合并进原冻结结果。

这套入口运行本地 HTTP 靶场上的真实模型任务，记录三个代码版本的实际行为。每个场景每版本一次，只用于小集试跑；稳定收益仍需重复、扩大任务集并复核交付质量。

```powershell
pnpm observe:projects --output test-results/observations/UNIQUE_ID
pnpm test:m6
pnpm m6 --prepare-only --id UNIQUE_PREPARATION_ID
pnpm m6 --run --id UNIQUE_RUN_ID
pnpm m6:resume --id EXISTING_RUN_ID
pnpm m6:resume --id EXISTING_RUN_ID --run
node scripts/m6/analyze.mjs --directory test-results/m6/UNIQUE_RUN_ID
```

默认只准备，不请求模型；`--run` 才会产生供应商用量。完整小集是三个场景乘三个版本，共九个项目实例，每个实例可能包含多次模型 API 请求。模型采用现有主模型，版本和端点指纹在调用前冻结；配置凭据不写入结果目录。

三个场景分别是有跨账户读取缺陷的文档服务、正确执行所有者授权的负对照，以及带旧拒绝响应、220 条背景观测和迟到 Hint 的访问检查。版本信息需作为信息结论保留。全部文档、身份和令牌均为本地合成数据，目标只监听当前独立容器的回环地址，不使用业务项目或工作区。

三个源码版本为 `c8ffdf5`、`101b9c9` 和当前工作区的业务源码快照。库从各版本源码独立打包，依赖锁必须一致，Pi SDK 固定 1.2.0，使用同一 Worker 工具镜像。不会切换 Git 分支或改动现有部署。当前候选的源码/包哈希、靶场、驱动、网关、判定器和调用顺序均记录在 `protocol.json`。

每个项目最多使用输入 100,000 tokens、输出 12,000 tokens、600 秒，单请求最多输出 4,096 tokens。所有角色、压缩、修复和重试合并计量；缓存输入不抵扣。网关在请求前使用保守的 UTF-8 上界和前次实际用量作准入，因此可能在实际 token 配额未用完时停止。此限制必须与模型行为分开说明，不能把准入停止解释为模型在精确配额下必然失败。未知供应商用量应停止后续调用，不按零计算；后续分析会复核错误响应及未结束请求的用量完整性。

驱动按生产 Dispatcher 的语义结算和继续调度。Run 已提交成功后发生的尾部异常、可重试审核失败或暂时无可领取任务，不能由驱动直接替换为整个项目失败。项目预算、业务图和 Store 的调度/重试规则决定继续条件。

结果在 `test-results/m6/ID/`：

- `protocol.json`：调用前固定的方案及哈希，保留初始状态。
- `results.json` / `summary.json` / `report.md`：原始小集汇总。
- `analysis.json` / `analysis.md`：按请求记录重新核对的样本资格、角色覆盖、失败阶段及共同有效场景；判断对照结论以这些文件为准。
- 各实例目录：初始/最终图、冻结报告、靶场访问记录、网关计量，以及脱敏的 Run 诊断、模型公开响应和用量记录。不会导出 SDK 隐藏思考、全局凭据或业务原始数据。

代码包位于 `.tessera/m6/ID/bundles/`。临时模型配置仅供容器读取，正常结束会删除；异常终止后应检查该次创建的 `private-model.json` 是否残留。保留预试验和正式实例的用量，不能丢弃失败后只展示成功结果。

中断后先用 `m6:resume` 检查。它核对全部冻结代码包、靶场、控制器、网关和判定器哈希，以及原 Worker 镜像；显式 `--run` 再核对当前模型配置，按原镜像 ID 和预算只执行尚未启动的样本。已有 `result.json` 的样本从磁盘汇入结果，不重复请求模型；有文件但没有最终结果的样本要求先对账。续跑使用互斥锁，保存独立的驱动哈希记录，保持原 `protocol.json` 不变。原协议中的 `running` 是冻结时状态，当前进度以 `summary.json` / `analysis.json` 为准。

费用缺少端点价格时保持未知。未完成交付的负对照不能因为没有漏洞输出就记为质量通过；没有进入 Review 时也不能据此评价审核调度、误报控制或信息类审核效果。
